# A–H 统一科研归档与恢复协议

版本：2026-10-11
适用仓库：`linkengde/-`（公开仓库）
适用对象：云端 A–H 在各自已批准任务范围内产生的、获准公开的科研结果

## 1. 权限与分支边界

用户已授权将已批准任务中可公开的科学输出上传到该仓库。该授权只覆盖科研结果的公开归档，不扩大任何计算任务范围，也不覆盖第三方许可、封存数据或各节点原有科学放行门。

每个节点只在自己的工作分支提交，例如 `cloud-d-b1-dft`。不得直接向 `main` 提交、重置、强推或改写历史；不得覆盖、删除或代替其他节点的分支和文件。提交前先 fetch 自己的分支，只有可以正常 fast-forward 时才 push。分支头已变化且无法无冲突快进时，停止、保留本地原件并报告 C。

A/B 已发布的成果按原状态保留，不搬动、不重算、不改数据角色。此协议适用于后续阶段快照及其补充，不要求重写历史提交。G/H 保持待命，没有新任务不得自行启动。

## 2. 每阶段归档内容

每个阶段以唯一的 task、attempt、stage 和 UTC 时间命名，例如：

`<task_id>/<stage>/<UTC_timestamp>_<attempt_id>/`

新归档必须使用从未存在过的路径。创建时若路径已存在，停止并申请新的 attempt ID；不得原位替换。已归档内容需要更正时，追加一个带原因、旧归档 ID、新归档 ID 和来源 SHA 的更正记录，旧记录仍保留。

归档应包含与该阶段相符的材料：

- 结构身份：元素、原子 ID/顺序、坐标、晶胞、PBC、父结构/父族、生成来源和输入哈希。
- MD 或采样：轨迹、速度/原子状态、温度与能量时间序列、步数和时间、随机数发生器状态、温控状态，以及可恢复的必要 restart/checkpoint。
- DFT：输入结构与参数、程序/环境版本、SCF 日志和收敛状态、native energy、free energy（若有）、单位、完整逐原子力及其原子顺序、验证日志。
- QA 与复现信息：QA 原始结果和判定、数据角色、task/parent/seed、脚本与配置 SHA-256、使用模型/势的名称和 SHA-256（仅记录身份，不因此上传势文件）、资源和耗时。
- README、机器可读 MANIFEST、覆盖归档所有内容的 SHA-256 清单。

任何收敛失败、数值不合格或 QA 未完成的阶段也可以归档，但 README、目录名和 MANIFEST 必须明确写为 `FAILED`、`INCOMPLETE` 或 `QA_HOLD`，并列明失败原因。未通过验收的输出不得登记为可训练标签或已验收参考。

## 3. 发布前检查与防覆盖

1. 等该阶段输出已经封闭，或确认 checkpoint/日志已原子化写完；不得打包正在被进程写入的半成品。
2. 核对 task ID、原子数与顺序、坐标/晶胞/PBC、配置 SHA、结果状态及所有值的有限性。
3. 检查仓库可见性、许可、数据角色和受限数据清单。公开仓库默认公开全部提交内容。
4. 先将完整 payload 写入新临时目录，生成 MANIFEST 和内部 SHA-256 清单；确认校验通过后再封装。
5. 归档 ID 必须唯一，先检查目标路径不存在。普通 Git 的每个提交 blob/文件最多 50 MiB；不得通过切片、改名或压缩来绕过单文件限额。
6. 对节点现有限制继续取更严格值：D/E/F Ag64 临时归档仍受已签署配置的单文件及总包上限（当前模板均为 50 MiB）约束。未获新的 C 配置前不得放宽。
7. 超限时停止 Git 上传。先提出 Git LFS 或其他持久存储方案，确认许可、容量、费用/配额和新目录恢复 SHA 测试后再使用。未验证备份前不得删除唯一有效副本。

建议包结构：

```text
<archive_id>/
  README.md
  MANIFEST.json
  INTERNAL_SHA256SUMS.txt
  payload/...
<archive_id>.tar
<archive_id>.SHA256SUMS.txt
```

内部清单列出包内每个文件（不自校验清单本身）；外部 sidecar 列出 tar 与同级归档说明文件。sidecar 自身的 SHA-256 记录在提交回执/节点报告中。若使用目录而非 tar，也必须提供等价的外层 manifest 摘要和逐文件清单。

## 4. 允许的远端归档与恢复流程

每个节点只能将自己的归档追加到自己的分支，并按以下顺序完成：

1. 生成并本地验证完整归档；保留工作输出和现有 checkpoint。
2. 正常提交并 fast-forward push 到自己的分支；记录 owner、分支、commit SHA、archive ID。
3. 在全新的空恢复目录中，从 GitHub 该分支独立 fetch/clone 该 commit；不能直接用工作 checkout 中的文件冒充远端恢复。
4. 核对 commit SHA、外层 SHA-256、内部 SHA-256、manifest 的 task/parent/stage/config 身份及归档状态。
5. 将文件恢复到另一个新目录，再次校验恢复后字节和 SHA。
6. 向 C 报告完整回执：来源本机路径、归档 ID、Git commit SHA、恢复目录、各层校验结果、数据状态、运行/归档时间和未解决问题。

任一 push、fresh fetch、提取或校验失败，停止后续续算和清理；修复备份通道后再请求 C 复核。远端成功读回只证明该份副本可取回，不证明本地 overlay 跨会话持久。不要删除唯一工作副本，除非另有经验证的恢复副本及保留计划。

## 5. 禁止进入公开仓库的内容

严禁提交 API key、token、私钥、cookie、认证配置、含凭据的环境转储；严禁上传封存 evaluator 的 TEST 坐标、标签或其它受限文件；严禁上传未获公开授权的第三方数据。版权论文 PDF 只有在明确许可允许再分发且项目负责人核准后才能上传；当前历史论文资料仍不随本协议公开。

不上传再分发许可未核实或明确禁止再分发的势函数参数文件。特别是 Ag.eam.alloy：归档中只记录文件名、版本/来源和 SHA-256；该参数文件不得打入归档。上传前人工检查 staged diff、manifest 与文件名，并运行可用的凭据扫描；不能确认的文件一律留在节点本地并向 C 报告。

## 6. 科学执行门独立有效

归档授权与计算授权相互独立。对 D/E/F 六个 Ag64 task，仍须满足势文件节点本地精确 SHA、E 的独立 synthetic upload/fetch/restore、实时资源与身份预检、Git 远端分支通道、QA 与 C 签署的暖机配置。第一候选仅为 D 的 `C-D-AGL-1250K-rho097-seed01`；在 C 正式签署前不得运行。通过首项暖机并完成 C 审核的远端恢复后，C 才决定是否逐项放行余下五项。不得自动接续 119,000 步。

G/H 继续待命；新增 DFT、MACE 训练、MD、TTM 或生产模拟均须各自已有授权，不得从“结果可以公开归档”推导执行许可。
