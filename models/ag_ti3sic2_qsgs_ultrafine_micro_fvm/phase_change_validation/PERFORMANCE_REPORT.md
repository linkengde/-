# 瞬态相变性能与云端资源报告

## 环境

- CPU配额：4核（cgroup `cpu.max=400000 100000`）。
- 内存上限：32 GiB（cgroup）。无可用NVIDIA GPU设备。
- 运行目录可用空间约51 GiB；三维焓法使用NumPy/SciPy CPU矩阵自由计算。
- 计时为实际Python墙钟；峰值RSS由进程`ru_maxrss`统计。具体数据不以稳态导热结果替代。

## 规模判断

- **内存：**已经完成的100³算例峰值RSS约0.61 GiB；旧稳态150³报告为约0.83 GiB，但不将它视作瞬态证据。根据100³实际瞬态进程内存，150³单场内存大概率仍在32 GiB以内；这只是分辨率外推，尚未实跑。
- **CPU：**100³纯Ag约4.9分钟，双层约12.1分钟；双连续QSGS 60分钟仍未完成，说明复杂结构的相变非线性迭代显著抬高成本。以此判断，两套150³完整加热—熔化—冷却循环在当前4核环境下不应启动。
- **正式长工况：**本测试热源仅1 ns，冷却窗口2 μs，不对应实际电弧持续时间。真实工况若要求更长物理时间，必须先有经验证的宏观热边界，再测量目标时间步与每个网格的求解成本。
- **算法性能：**FFT常系数周期拉普拉斯预条件器降低了线性迭代成本，但QGS相变区仍需大量阻尼Newton步骤，且会触发自适应回退。后续性能改进优先考虑代数/几何多重网格或可验证的预条件器，并保存每一阶段检查点。
